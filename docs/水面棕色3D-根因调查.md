# 水面棕色 3D 渲染问题 · 根因调查（M7）

日期：2026-09-30
状态：**根因已定位**——引擎级限制，数据文件不可绕过；附两个可执行替代方案。
工具：`tools/diff_water_artdef.py`（原版/自定义水地形条目全路径结构化 diff，可复跑）。

## 一、问题陈述

自定义水地形 `TERRAIN_RR_RIVER`（大河水面）与 `TERRAIN_RR_SHALLOW`（浅海）在
3D 世界视图渲染为**棕色**（无水面裸地观感）；小地图/战略视图蓝色正确。
`TERRAIN_RR_DEEPSEA`（深海，借 OCEAN 壳）3D 正常。

已排除（M4~M6 各轮实机试验）：artdef 加载链路（.dep + UpdateArt，ArtDef.log
已确认 `Added art file 'RRMap: …' to the ArtDefProvider`）、条目字段不一致、
TerrainType Xref（Shallows→Ocean 无效）、Clutter（清空无效）。

## 二、决定性 A/B 事实

| 地形 | DB 标志 | artdef TerrainType Xref | 3D 结果 |
|------|---------|------------------------|---------|
| TERRAIN_COAST（原版） | Water + **ShallowWater** | Shallows | ✅ 蓝 |
| TERRAIN_OCEAN（原版） | Water | Ocean | ✅ 蓝 |
| TERRAIN_RR_DEEPSEA | Water | Ocean | ✅ 蓝 |
| TERRAIN_RR_SHALLOW | Water + **ShallowWater** | Ocean（M5 起） | ❌ 棕 |
| TERRAIN_RR_RIVER | Water + **ShallowWater** | Ocean（M5 起） | ❌ 棕 |

artdef 侧三个水条目与原版 COAST/OCEAN **全路径结构化 diff 完全一致**
（`tools/diff_water_artdef.py`，含父链/集合名/元素名/字段名/值；当前文件唯一
差异即 M5/M6 两处刻意试验：Xref 改 Ocean、Clutter 清空）。`.dep` 接线与原版
Expansion2.dep 逐字段一致（消费者 9 项名单、ArtDefDependencies=[StrategicView,
Clutter] 均核对无误，见 `mod/RRMap.dep` 头注释）。

**深水路径对自定义地形完全开放，浅水路径不开放**——两条目加载机制相同
（同一 .dep、同一根集合并集、同一次注册），唯一能解释四格 A/B 表的变量只剩
DB 的 `ShallowWater` 标志（与地形类型身份）。

## 三、引擎机制证据链

1. **渲染器二进制**（`Civ6.app/Contents/MacOS/Civ6_Exe_Child`，60 MB 引擎本体）：
   含 `Shallows`、`ShallowsMtl`、`CoastlineLayer`、`OceanLayer`、`WaterType`、
   `WaterLibrary`、`WaterPackageEntry` 等**编译期写死的 artdef 字段名**；附近
   源文件路径暴露相关模块：`Civ6/Src/App/Graphics/WorldView/WorldView_TerrainContext.cpp`、
   `Civ6/Src/App/Engine/TerrainFeaturelineDatabase.cpp`、`CivTech/Libs/Terrain/Terrain_Cell.cpp`。
   即：3D 地形按"分层"渲染——`LayerSet_Default`（原版 TerrainStyle.artdef）把
   CoastlineLayer（浅水岸线）/OceanLayer（深水）等层装配到地块上。
2. **渲染器无地形名字面量**：`Civ6_Exe_Child` 中 `TERRAIN_*` 字符串为零——
   排除"按 Type 名字符串特判"的实现方式；GameCore 里的 `TERRAIN_COAST/OCEAN`
   字面量位于 Tiled 地图导入器（`LoadPlotsFromTiled`），与渲染无关。
3. 结合 A/B 表：浅水（ShallowWater=true）地块走 CoastlineLayer 特殊路径，
   该路径**不解析自定义地形在 Terrains.artdef 的并集条目**（Xref 换 Ocean
   无效 = 该路径根本不读条目的 TerrainType Xref；条目逐字段克隆无效 = 不读
   条目任何字段）；未命中即不挂水面/岸线 → 露出裸地（棕）。
   深水（Water=true）路径是通用水面（按 Water 属性/深水层），自定义类型
   照常解析 → RR_DEEPSEA 蓝。两种子实现（按 ShallowWater 标志分支 / 按地形
   恒等缓存岸线定义）数据侧均不可绕过，结论一致。
4. **社区负空间证据**：
   - 本机 190 个订阅 workshop mod 全样本扫描：`.artdef` 中自定义 `TERRAIN_*`
     条目 **0 个**；DB 自定义地形行 0 个（除本 mod）。
   - Sukritact's Oceans（2542898147，最知名的海洋内容 overhaul，artdef 加载
     实证正常）：**不新增任何自定义水地形**，全部内容（海带/珊瑚/龙虾等资源、
     礁体地貌、渔业设施）挂在原版 `TERRAIN_COAST` 上；其 `.dep`/artdef 做法
     与本 mod M4 修复后的接线一致（无更多可抄）。
   - 公开网络检索无"自定义浅水地形成功渲染"或失败讨论——该方向无人做成过。

## 四、根因结论

> **Civ6 引擎的浅水（ShallowWater）3D 渲染路径（CoastlineLayer：半透明浅水、
> 岸线泡沫、沙滩混合）对 mod 合并进 Terrains.artdef 的自定义地形条目不做解析，
> 仅原版 TERRAIN_COAST 类型可获得该路径；自定义浅水地形回落为无水面裸地（棕）。**
> 深水路径无此限制（RR_DEEPSEA 实证）。此为引擎行为，artdef/dep/DB 数据文件
> 层面不可修复；M5（Xref）、M6（Clutter）两轮试验的失败均由该结论解释。

## 五、可执行替代方案（择一，需所有者裁决）

### 方案 a：水面退回原版 COAST 地形（观感优先，推荐）

浅水水面写回 `TERRAIN_COAST`（3D 必蓝——每块原版海岸都是它），具名让位：

- 地图脚本 `mod/Maps/RR_Continents.lua` `waterMatrix`：`["浅海"] = {"TERRAIN_COAST", "TERRAIN_COAST"}`；
  `GetRiverTerrainType()`（约 L1528）返回 COAST。RR_RIVER/RR_SHALLOW 的
  DB 行与 artdef 条目可保留（闲置无害）或下轮清理。
- `TERRAIN_RR_DEEPSEA` **保留具名**（深水 3D 正常，不受本问题影响）。
- 具名回收（后续里程碑）：地块 Property 标记形态（浅海/大河水面）+ 覆盖
  `PlotToolTip` UI 脚本的悬停文本；小地图天然正确。
- 代价：悬停文本在新 UI 落地前显示"海岸"；浅海/大河失去独立产出列
  （当前壳等价下与 COAST 同值，损失为零）。

### 方案 b：保持现状（机制/具名优先）

保留 RR_RIVER/RR_SHALLOW 具名水卡与全部机制；接受 3D 视图棕色水面，
小地图/战略视图蓝色正确。零改动。

### 附：不采用的第三法（记录在案）

删除两个浅水地形的 `ShallowWater="true"`，令其走通用深水渲染路径（推测转蓝，
与 A/B 表一致）。**不采用理由**：未经实机验证（禁启动游戏）；且改变玩法语义
（浅水规则——岸线设施/早期海军等 GameCore 行为随标志变化），违反"壳等价"
纪律。若所有者愿试，改动仅 `mod/Data/RR_Terrain.xml` L18 与
`mod/Data/RR_Terrains_Matrix.xml` L48 各删一属性，一行回滚。
