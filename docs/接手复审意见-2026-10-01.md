## A. 裁决记录与落地方案

### A1. 生成链保留；补"输出端引擎映射表"（初稿见第 5 节）

问题重述：三层正交模型（8 形态 × 6 地带 × 9 微地貌）概念上成立，但引擎内每格只有一个 Terrain 类型（丘陵/山地是行属性 Hills/Mountain，官方 MapEnums.lua 注释明言），且自定义地形/地貌类型的 3D 渲染路径不可用（旧实现 M7 实测棕色错误外观）。因此生成器的输出必须收敛到**原版地形 + 原版 Feature + 自定义属性（Property）**三件套。

已起草映射表初稿（第 5 节），结论：**不需要任何自定义地形/地貌类型**，全部借壳原版，绕开渲染墙。三个数值取舍点（山地移动 3、冰川山地通行、沼泽/河漫滩数值方向）不阻塞生成器开发，归数值框架阶段裁决。

### A2. 海拔等级化（已写入总案决策#14 注记 + 第一部分 1.3）

- **持久化字段 = 高程等级（小整数）**，存档体积小、判定直接。
- **连续米值仅生成期存在**：算水流方向、坡度、汇流，生成结束即丢弃，不入存档。
- 一切规则判定（隆起、形态归类、AI、地图模式）只读等级——旧版"大片丘陵"的病根就是拿连续高差做隆起判定，此路封死。
- 气象模块（第六部分）读等级；若需名义海拔，用等级的固定代表值映射（如等级 3≈1000m）。
- 存储机制：`plot:SetProperty("RR_ElevLevel", n)`，随存档序列化（官方场景 PiratesScenario/BlackDeathScenario 地块级先例已验证）；生成期→开局经官方桥梁 `LuaEvents.NewGameInitialized`（EarthMaps/*.lua 先例）写入。

### A3. 大河 = 1—2 格宽的水面带，生成优先（第一部分 C 类河流卡注记已改）

- 生成期把河道沿线格直接写成 `TERRAIN_COAST`——就是"小一点的海"，原版渲染、寻路、海军通行、湖泊语义全部免费获得（原版湖泊即 COAST）。
- v1 实现范围到此为止。泅渡减力、河流等级限制、渡口通行等机制细节归第三部分「合纵连横」设计，届时再选机制（Feature/Modifier/操作拦截）。
- 生成器侧河流分两级即可：小河=原版边缘属性（AddRivers 逻辑），大河=水面格带（自写河道下切）。

### A4. 尺寸锚点修正（已写入第一部分附录）

- 正式档：**标准 1:4 = 168×108 = 18,144 格**（原版 STANDARD 84×54 各维×2）。
- 测试档：**≤120×78（9,360 格）**，供快速迭代（沿用旧版 STD10 思路）。
- 性能验证以这两档为准，Huge 不做规划。

## 5. 引擎映射表（初稿 v0.1，待所有者裁决后并入第一部分策划案）

载体三件套：**原版地形（视觉+基础通行）+ 原版 Feature（可叠加语义）+ plot Property（数据层，自定义标签）**。

### 5.1 水域

| 策划形态 | 引擎载体 | 说明 |
|---------|---------|------|
| 深海 | TERRAIN_OCEAN | 原版即远洋 |
| 浅海 | TERRAIN_COAST | 原版即大陆架浅水 |
| 海岸/水面（含大河、湖泊） | TERRAIN_COAST | 大河=1—2 格宽 COAST 带；河流等级/河湖区分走 Property；原版湖泊即 COAST |

### 5.2 陆地（Layer1 形态 × Layer2 地带）

| 策划组合 | 引擎载体 | 说明 |
|---------|---------|------|
| 低地×森林 | GRASS/PLAINS + FEATURE_FOREST；热带高降水用 FEATURE_JUNGLE（=雨林） | 原版森林/丛林自带防御+3、移+1 |
| 低地×草原 | GRASS（湿润）/ PLAINS（半干） | 产出差异由地形行+地带标签表达 |
| 低地×荒漠 | DESERT | |
| 低地×苔原/冰原 | TUNDRA / SNOW | |
| 低地×农耕开发区 | 底地形不变 + 农场改良 + Property | 非自然生成（3.4 演替产物），无需地形 |
| 隆起×任意地带 | 对应 *_HILLS | 原版丘陵防御+3 与设计直觉一致 |
| 山麓 | *_HILLS + Property"山麓" | 视觉并入丘陵，数据层区分；移 2 与设计一致 |
| 山地 | *_HILLS + Property"山地" | ⚠️**取舍点 1**：原版 *_MOUNTAIN 不可通行（Impassable），山地要可通行只能借壳 HILLS；移动消耗 2 vs 设计 3 的差异归数值框架（静态表覆盖或 Modifier） |
| 主脊 | *_MOUNTAIN | 原版即不可通行 ✓ |
| 山口 | 缺口格写 *_HILLS | "连绵群山+隘口"用纯原版机制成立 ✓ |
| 雪线/冰川（盖山地/主脊） | SNOW_HILLS / SNOW_MOUNTAIN + Property | ⚠️**取舍点 2**：冰川山地借壳 SNOW_HILLS 保持可通行（形态归类不变）；主脊段 SNOW_MOUNTAIN |

### 5.3 微地貌（Layer3）

| 策划微地貌 | 引擎载体 | 说明 |
|-----------|---------|------|
| 河漫滩 | FEATURE_FLOODPLAINS（本体三变体：GRASSLAND/PLAINS/DESERT） | 原版自带 RequiresRiver 约束；原版防御-2 vs 设计-1，数值覆盖归数值框架 |
| 三角洲 | FLOODPLAINS 借壳 + Property"三角洲" | 河口格 |
| 沼泽/湿地 | FEATURE_MARSH + Property | ⚠️**取舍点 3**：原版 MARSH 防御-2 与设计+4 方向相反——改表覆盖或 Lua 结算，归数值框架 |
| 绿洲 | FEATURE_OASIS | 原版自带 AddsFreshWater="荒漠唯一淡水" ✓ 与设计完全同构 |
| 火山 | FEATURE_VOLCANO + FEATURE_VOLCANIC_SOIL | 风云变幻原生，含喷发灾害 |
| 地热 | FEATURE_GEOTHERMAL_FISSURE | 风云变幻原生 ✓ |
| 峡谷 | Property 标记（山地壳+河道沿线） | 通道语义由数据层+地图模式表达 |
| 瀑布/急流 | Property 标记 | 航运阻断机制归第三部分 |
| 浅滩/渡口 | Property 标记；海上浅滩可借壳 FEATURE_REEF | 渡河点机制归第三部分 |

### 5.4 结论

全表零自定义地形/地貌类型，旧实现撞死的渲染墙整体绕开。生成器 v1 的输出空间=上表左列，右列即落盘格式。三个取舍点不阻塞生成器，归数值框架阶段。
